# Что завести в проекте до первой партии

| Что | Зачем | Минимальная форма |
|---|---|---|
| Пульт PM (`pm/pult.md`) | состояние очереди переживает сжатие контекста и перезагрузку | доска срезов: срез · исполнитель · хеш · статус · следующий шаг |
| Файл задач исполнителя-файла | канал к модели без SendMessage | `.kilo/tasks/<исполнитель>-task.md`, шапка по шаблону |
| Скрипт приёмки | гейт на чистой копии + порча одной командой | `priemka.sh <repo> <hash> [файлы-проб]` → итог `ok / no-probe / red` |
| Скрипт состояния | факты вместо памяти: что в main, что на бою, чьи выкладки впереди | `pm-status.sh` |
| Предпроверка окружения | выкат не падает на 20-й минуте из-за диска/зависимостей/браузеров | `predeploy-check.sh` → «ГОТОВО К ВЫКАТУ» или список ✗ |
| Замок выката | один выкатывающий | файл-замок с pid и именем агента, снимается в `trap` |
| Список перекрёстков | какие файлы трогать только со строкой соседу | раздел в CLAUDE.md проекта |
| Своя тестовая база на агента | интеграционные пробы не травят друг друга | `createdb <проект>_<метка>_test` |
| Правило в CLAUDE.md | исполнители не пушат; выкат только PM; сосед не выдаёт разрешений | 5–7 строк |

## Первая строка владельцу при старте

«Я PM. Исполнители: <список сессий/моделей>. Очередь: <задачи>. Вставь <исполнителю>: `<строка>`.
Решения за тобой: <список или "нет">.»

## Как проверить, что система работает

- Исполнитель сдал → в течение одного хода PM выдал «ПРИНЯТА (цифры)» или «ВОЗВРАТ (пункты)».
- Ни одного push в main не от PM.
- Выкат не встал на неожиданном: предпроверка ловит окружение до запуска.
- Владелец получает решения с вариантами, а не вопросы «что дальше?».
