# UX/UI Review & Craft — на фундаменте источников истины

Этот скилл — обязательный вход в любую UX/UI-работу. Он держит «север» (мировые стандарты), курирует, к каким репозиториям обращаться под конкретный продукт, и даёт проверяемый метод оценки. Создан из реальных правок и ревью живой учебной платформы.

## Когда применять (ОБЯЗАТЕЛЬНО)

Любая работа, которая меняет, как продукт **выглядит, ощущается, движется или с ним взаимодействуют**: новый экран/страница/компонент; выбор стиля, цвета, типографики, спейсинга; навигация/IA; ревью UI; фикс UX-бага; «сделать профессиональнее/понятнее/доступнее». **Если меняешь look / feel / flow — сначала сюда.** Не нужен только для чистого бэкенда/API/инфры/не-визуальных скриптов.

## Жёсткий процесс — 3 гейта (НЕ пропускать)

1. **Консультация со скиллом.** Прочитай этот SKILL.md + `references/sources.md` + `references/framework.md`. Не дизайнь и не ревьюй «по памяти».
2. **Курация источников под КОНТЕКСТ продукта.** Определи тип продукта (веб learner-facing / нативный-мобайл / admin-SaaS / маркетинг-лендинг / e-commerce …) и аудиторию. По контексту выбери, какие стандарты и репозитории консультировать, и **отсеки нерелевантное** (см. фильтр в `references/sources.md`).
3. **Только потом — выполнение** (дизайн или ревью). **Бренд-код проекта + фундамент — ВЫШЕ дефолтов любого скилла.**

## Истина выше инструментов

Фундамент (NN/g · WCAG 2.2 · Laws of UX · Material 3 · Apple HIG · WAI-ARIA APG · Refactoring UI · GOV.UK) — это «север». Дизайн-скиллы (`ui-ux-pro-max`, claudekit, и т.п.) либо операционализируют фундамент, либо тянут не туда. Пример из практики: `ui-ux-pro-max --design-system` под образовательную веб-платформу выдал **claymorphism + Baloo 2** (детско-игровой, мобайл-идиомы) — это **ОТСЕКАЕТСЯ**; у этого скилла берём только **UX-чек-листы** (a11y/навигация/формы/layout). **Полировка ≠ юзабилити: ясность и простота важнее «вау».**

## 12 принципов (рабочая призма)

1. Минимум когнитивной нагрузки (чанки, progressive disclosure). 2. Конвенции (Jakob) — не изобретать. 3. Видимость важнее памяти. 4. **Один primary-CTA на экран** (вторичные — подчинены). 5. Plain language, понятно за <3 сек; жаргон поясняется при первом упоминании. 6. Предотвращение ошибок > восстановление. 7. A11y — фундамент, не косметика. 8. Сканируемость/иерархия (размер/контраст/вес, не цвет). 9. Воздух/whitespace. 10. Мгновенный feedback (<400ms). 11. Контроль и пути выхода. 12. Итерации на реальных данных.

## Для РЕВЬЮ — 7-мерный фреймворк + метод (детали → `references/framework.md`)

Оценивай по 7 измерениям, 0–100 каждое + общий **first-time usability score**; кросс-чек по 10 эвристикам Nielsen:
**1) Навигация и IA · 2) Ясность для новичка / cognitive-load · 3) Визуальная иерархия / layout · 4) Доступность WCAG 2.2 AA · 5) Консистентность / микрокопирайт · 6) Интеракции / обратная связь · 7) Frontend-quality (UX-перф — на этап сборки).**

**Метод (масштабируемо):** параллельные рецензенты-по-измерению смотрят **реальные рендеры** экранов → структурные находки `{экран, проблема, severity, критерий/стандарт, фикс}` → **адверсариальная верификация: находка засчитывается только при ≥2 независимых подтверждениях** (скептик-проверяющий с пиксель-замером/трассировкой кода — отсекает преувеличения) → агент-«новичок» по сценарию 18F (information scent, жаргон) → scored-отчёт + приоритизированные фиксы → правки → перерендер до/после + vision-QA. Картинки смотреть сабагентами (текстовый вывод), не накапливать в своём контексте.

## Для ДИЗАЙНА (когда строишь, а не ревьюишь)

Бренд-код первым (сверься с бренд-буками/токенами ДО дизайна). Один primary-CTA на экран. Plain-language + глоссинг жаргона инлайн. Mobile + a11y закладывай с самого начала, не «потом». Реюзай доступные веб-паттерны (Radix/shadcn, WAI-ARIA APG) вместо кастома. После — прогони себя по 7 измерениям как мини-ревью.

## Что НЕ брать из скиллов (anti-patterns)

- `ui-ux-pro-max` → его **style/palette-движок** (claymorphism/Baloo и пр.) и **мобайл-нативные правила** (haptics/safe-area/gestures) — для веба не годятся; бери только чек-листы.
- **admin-SaaS-плотность** (shadcn-admin) / **маркетинг-конверсию** (лендинг-тактики, paywall-FOMO) / **декор** — отсекай, если продукт learner-facing/контентный.
- Любой дефолт скилла, что противоречит бренд-коду проекта или фундаменту, — игнор.

См. полную карту источников и курацию → **`references/sources.md`**; детальный фреймворк, рубрику и метод → **`references/framework.md`**.

Правила, которые мы добавили поверх фундамента по итогам приёмок (макет, двуязычие, текст как функция, проверка в браузере), → **`references/project-rules.md`**.
