# Правила поверх фундамента — из реальных приёмок

Фундамент (NN/g, WCAG 2.2, Laws of UX) говорит, как должно быть. Эти правила говорят, где мы
ошибались на практике и чем это ловить. Каждое появилось после конкретного дефекта.

## 1. Утверждённый макет — источник интерфейса

- Если у экрана есть утверждённый заказчиком макет, строим строго по нему: структура, блоки,
  классы, подписи. Из макета не берётся только «что делает экран».
- **Ни одна видимая строка и ни один элемент управления не появляются, если их нет в макете или
  в ТЗ.** Придуманная подпись — дефект, а не мелочь.
- Экран не сдаётся каркасом «пока без вида». Блок без данных показывается пустым состоянием или
  не показывается, но структура макета не упрощается.
- Проверка перед сдачей: открыть файл макета этого экрана, сверить список блоков и классов.
  Реальный случай: экран собран своей вёрсткой — 11 блоков против 68 в макете.
- Утверждённые тексты — в отдельных файлах словарей, а не в компонентах. Тест падает, если на
  экране появилась строка вне словаря.
- Расхождение макета с ТЗ поднимается владельцу, сам не выбираешь.

## 2. Все языки — с первого экрана

- Экран на одном языке — несданный. Словари языков совпадают по составу ключей (тест).
- Перевод, который есть в макете, переносится, а не делается заново.
- Чего в макете нет — переводим сами, профессионально: термины (CRM, KPI) латиницей, падежи при
  подстановке дат и чисел проверяем.
- Проверки на бою по тексту — на всех языках интерфейса, иначе проба слепа к половине
  пользователей.

## 3. Текст на экране — это и есть функция

- Непрочитанная подсказка равна отсутствующей.
- Одна мысль, максимум два предложения. Говорить последствие или условие, а не название кнопки:
  «Переделать можно, пока трекер не принял», а не «Нажмите "Сохранить", чтобы сохранить».
- Отказ = причина + выход: «Связь оборвалась. Проверьте интернет и выберите файл заново».
- Конкретика вместо общего: «PDF, DOCX, XLSX, до 10 МБ», а не «популярные форматы».
- Без слов-пустышек: «пожалуйста», «просто», «удобно», «в несколько кликов».

**Где подсказка нужна:** необратимое действие или неочевидное последствие; невидимое условие
доступности («почему кнопка серая»); новая для человека вещь (ИИ, автоперевод, распознавание
речи); пустой экран; отказ.
**Где не нужна:** навигация, очевидные действия («Сохранить», «Скачать»), повтор уже сказанного,
«для симметрии». Если объяснять приходится дважды — чинить интерфейс, а не текст.

## 4. Проверка — в браузере, на том процессе, что отвечает сейчас

- Отчёт исполнителя прогоном не считается. Пройти сценарий целиком тем путём, каким пойдёт
  пользователь: завёл → назначил → вошёл другой ролью → увидел результат.
- Ширины минимум 390 и 1440. На 390 у страницы нет прокрутки вбок.
- Консоль браузера без ошибок на каждом задействованном экране.
- После правки сервера — пересборка и перезапуск, и проверка, что отвечает новый процесс.
  Реальный случай: фикс «подтверждён», а стенд отвечал старым кодом из памяти процесса.
- Строка в DOM не доказывает, что человек её видит: мерить видимость и размер, а не наличие.
- Демо-данные до и после сверены, всё созданное убрано. Браузеры закрыты за собой.

## 5. Как это входит в ревью по 7 измерениям

| Измерение | Что добавляют эти правила |
|---|---|
| Консистентность / микрокопирайт | сверка со словарём и макетом; ни одной выдуманной строки; все языки |
| Ясность для новичка | подсказка только там, где она заслужила место |
| Визуальная иерархия | структура макета не упрощена; блоки на месте |
| Доступность | 390 без горизонтальной прокрутки; фокус и подписи в разметке |
| Интеракции / обратная связь | отказ с причиной и выходом; пустые состояния |

Находка засчитывается при ≥2 независимых подтверждениях: второй голос — скептик с замером
(пиксели, трассировка кода, скриншот), а не согласие первого.
