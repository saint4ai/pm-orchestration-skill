# 7-мерный фреймворк ревью + рубрика + метод

## Измерения (0–100 каждое; цитируй конкретный принцип/стандарт в каждой находке)

1. **Навигация и IA** — консистентность размещения нав; persistent-nav из глубоких страниц; предсказуемый back; **нет избыточных/дублирующих действий** (напр. кнопка «На главную» в hero при «Главная» в навбаре); **ОДИН primary-CTA на экран** (вторичные подчинены); активное состояние текущего пункта; breadcrumb на глубине 3+. *(NN/g #2/#4, Jakob, WAI-ARIA APG, 18F IA)*
2. **Ясность для новичка / cognitive-load** — information scent (за 3 сек понятно, что это и что делать дальше); **глоссинг жаргона** при первом упоминании; progressive-disclosure vs перегруз; осмысленные empty/loading/error; time-to-first-value; число выборов на экране (Hick/Miller). *(NN/g e-learning, 18F usability)*
3. **Визуальная иерархия / layout** — иерархия через размер/контраст/вес (**не цвет**); сканируемость; ритм отступов 4/8; воздух; заметность главного действия; длина строки 60–75; выравнивание. *(Refactoring UI, Apple HIG Clarity)*
4. **Доступность WCAG 2.2 AA** — контраст текста ≥4.5:1 (крупный 3:1) — **меряй пиксели, не на глаз**; видимый focus и не перекрыт; всё с клавиатуры; заголовки h1→h6 без пропусков; label=видимый текст у инпутов; alt; ARIA для icon-кнопок/меню; skip-links; **цвет не единственный носитель смысла**; reduced-motion; цели ≥24px. *(WCAG 2.2, WAI-ARIA APG)*
5. **Консистентность / микрокопирайт** — единые лейблы/иконки/термины между экранами; тон; CTA говорит результат; ошибки «причина + как исправить», **не винят юзера**. *(NN/g #4 + error-guidelines, ux-patterns)*
6. **Интеракции / обратная связь** — affordance (понятно, что кликабельно); видимые стейты hover/focus/disabled/active; feedback <400ms (Doherty); форм-UX (label/inline-validation/error-recovery/required); пустые/загрузочные. *(ui-ux-pro-max §2/§8, Radix)*
7. **Frontend-quality (UX-перф)** — LCP/TTI/INP; без layout-shift; без async-waterfalls. **На этап реальной сборки фронта**; для статичного мокапа — не блокер, помечай как build-time. *(Vercel react-best-practices)*

**Общий score** = взвешенное среднее (или простое среднее) → «first-time usability score». Кросс-чек по 10 эвристикам Nielsen. В отчёте: оценка по измерениям + общий + «что сильно» + подтверждённые дефекты (приоритет) + системные темы + что вне мокапа.

## Severity
`critical` (ломает задачу / провал AA / тупик) · `major` (заметно вредит новичку) · `minor` (полировка). Верифицируй critical+major; minor можно не верифицировать.

## Метод (масштабируемый, адверсариальный)

Под капотом — оркестрация (Workflow), если масштаб большой; для мелкого — последовательно.

1. **Рендеры.** Сними реальные рендеры всех экранов (десктоп + мобайл; tablet если важно) Playwright-ом. Картинки смотри **сабагентами с текстовым выводом** — не накапливай изображения в своём контексте (триггерит лимит many-image).
2. **Параллельные рецензенты — по одному на измерение.** Каждый читает этот фреймворк + смотрит рендеры + возвращает структурно: `{экран, проблема, severity, критерий/стандарт, why (вред новичку), fix}`. Плюс отдельный **агент-«новичок»** (сценарий 18F: «что это за сайт? первые впечатления?») — holistic-проход по ядру задач.
3. **Адверсариальная верификация.** Каждая critical/major-находка → независимый **скептик** (по умолчанию ОПРОВЕРГНИ, если не очевидно): смотрит тот же экран, **меряет пиксели/трассирует код**, выносит `{isReal, confidence, note}`. **Находка засчитывается только при ≥2 подтверждениях.** Это критично — иначе плодятся ложные (типичные ложные: «текст не проходит AA» там, где по факту 5:1; «нет валидации формы» на resting-state скриншоте; жаргон, который = родной язык ЦА).
4. **Синтез.** Scored-отчёт + приоритизированный список подтверждённых фиксов. Сохрани как артефакт (`docs/ux-research/<variant>-ux-review.md`).
5. **Фиксы → перерендер до/после → vision-QA → деплой превью.** Бренд-код — выше палитр любых скиллов.

## Якорные ошибки-предостережения (из практики)
- Не доверяй «зелёному» отзыву рецензента без верификации (зелёная сьюта ≠ нет багов).
- Контраст — **меряй**, не на глаз. Жаргон — отличай «технический» от «родного языка ЦА» (ICF для коуча — родной; «поток»/«супервизия» — поясняй).
- Мокап статичный → runtime-состояния (ошибки/empty/loading), перф — это build-time, не дефект мокапа.
- Глоссинг в мелком канвасе — инлайн-текстом (1px-пунктир сабпиксельный, не виден).
